## 仍需用户真实目录授权检查

自动化内存目录替身只能验证读写顺序与失败处理，不能证明操作系统原生文件选择器的授权行为。以下步骤应在用户实际使用的 Chrome/Edge 和目标磁盘上执行；未执行前不得宣称真实目录授权已验证。

1. 在开发分支入口打开两个功能，各建两个项目；在支持图片/附件的模块导入一个小文件。
2. 打开“备份与恢复”，选择一个专用空备份父目录；允许浏览器读写。若 API 不可用，改用 ZIP，不能通过外部脚本绕过授权。
3. 点击“立即备份全部到目录”，检查出现独立时间目录、modules/shared 等层级，以及最后生成的 manifest.json、complete.json；再次备份产生新目录，旧目录内容保持不变。
4. 关闭浏览器再打开，检查是否需要重新授权。取消或拒绝时应明确提示，不标记成功；目录句柄只显示目录名，不承诺完整系统路径。
5. 在另一个干净浏览器配置中检查该时间目录或 ZIP，默认以副本恢复；切换到恢复项目，检查输入、动态行、图片/附件及原理图布局能继续编辑。
6. 对测试备份的复制件删除一份附件、修改 project.json 或移走 complete.json。检查应指出损坏/未完成，不覆盖正常浏览器数据；切勿故意破坏唯一备份。
7. 恢复时明确选择替换目标，确认恢复点；验证回退。恢复后另做新编辑，再尝试旧恢复点回退，应阻止覆盖并提供另存旧项目副本。

本地备份可用于恢复业务数据，不自动修复程序、浏览器权限、存储配额或磁盘故障。备份本身含工程参数和附件，应放在用户认可的本地位置，不自动上传仓库。
