# 功能内多项目与本地工作区备份设计

日期：2026-10-21。基线：v2.1.1，`73404f8`。

状态：用户已于 2026-10-21 审阅确认，进入实施计划阶段。本文不是已实现功能说明。

## 1. 目的与边界

每个计算、校核和工程文档功能内部可命名、保存、切换多个项目。新项目从该功能的默认模板开始，旧项目可恢复续做。全局不增加业务项目，不改变现有单侧功能导航，不建立跨模块同名项目关联。

新增公共备份入口，将当前浏览器此计算器工作区的全部用户工作数据按功能、项目分层导出到用户授权的本地目录；备份支持完整恢复和局部恢复。仍为纯静态、离线优先应用，无后端、账号、云同步或新增构建要求。

首版不做双向自动同步、后台自动覆盖本地文件、跨模块参数联动、工程参数自动纠错；不更改既有计算方法，不恢复旧 K 算法。此次不自动升产品版本或推送 GitHub。

## 2. 已核实的现有结构

- `js/app.js` 负责模块切换、渲染、草稿捕获和保存。当前保存异步完成，但切换未等待保存成功；必须改为可等待的切换流程。
- `js/drafts.js` 以模块 ID 保存一份 `{form, model, tabs, details}`；IndexedDB 与 localStorage 应急副本均存在，不能通过删除旧库实现升级。
- 模块可提供 `captureDraft`、`restoreDraft`、`refreshDraft`、`resetDraft`。固定表单和动态模型需分别适配，不能只保存 DOM 输入值。
- 估价的模块模型跨 render 存活，并使用 `electrical_toolkit_part_estimator_v1`；IEC 有 `electrical_toolkit_iec60664_verification_v1`；材料库有 `matdb_override` 和 `matdb_custom`，必须纳入隔离或备份。
- `index.html` 显式加载所有离线依赖，已有本地 JSZip；开发依赖不作为浏览器运行依赖。
- 共 19 个注册模块，详见 `README_AI开发交接.md`。原理图、螺栓、DVP、SOR、IEC 等附件、动态模型、导出行为必须保留。

## 3. 用户界面

### 3.1 功能内项目工具栏

计算/校核/文档模块标题下方增加公共工具栏：

`当前项目：[名称 ▼]  新建  重命名  复制  导入项目  导出项目`

项目列表显示名称、最近修改时间。名称可重复但以唯一 ID 区分；空白名称不接受，名称最多 120 个字符。新建时建议名为“新项目 1”等。列表仅列出当前功能项目。项目管理弹窗提供二次确认删除，至少保留一个项目；删除前可导出，不连带删除其他功能或本地历史备份。

工具栏状态区明确区分“未保存”“保存中”“已保存至浏览器”“保存失败”。恢复默认值仅重置当前项目，需确认，不删除其他项目。

材料库、标准库、工程公式页保持查询页身份，不强加业务项目选择器；保留查询草稿，其用户编辑/自定义数据和查询状态同样纳入全量备份。材料库的新增材料不因新建或重置其他功能项目而清空。

### 3.2 公共备份入口

导航区域提供“备份与恢复”，打开对话框而非增加业务项目栏。提供：选择/更换目录、立即备份全部、下载 ZIP 备份、从目录/ZIP 恢复。

显示目录名称、授权状态、最近成功备份时间、已备份快照版本、是否存在未备份更新。浏览器已保存不等于已本地备份。未选择目录、授权失效或不支持目录 API 时，明确展示状态并提供 ZIP 路径，不静默降级为已写入目录。

## 4. 项目数据与模块接口

### 4.1 存储模型

新增独立版本的工作区数据容器，不将产品版本、项目容器版本、模块业务 schema、备份格式版本混为一谈。

每个项目记录包括 `id`、`moduleId`、`name`、`createdAt`、`updatedAt`、单调 `revision`、`appVersion`、模块适配版本和 `payload`。payload 保留原有 form/model/tabs/details 结构；已有模型内项目名等业务字段保留，不盲目覆盖。对已有报告名称设置提供模块适配，使导出文件标识当前功能项目，报告内原有零件/报告标题仍保留。

每模块保存一个活动项目 ID；工作区保存全局 revision、公共用户数据与恢复点目录。新模块项目不复用另一模块的 ID 或状态。全量读取需覆盖尚未打开的功能，而不是只遍历当前 DOM。

IndexedDB 优先持久化，兼容原有应急副本思路。写入失败不可将内存缓存当作成功；只有至少一个持久化通道成功才显示浏览器已保存。大附件超出 localStorage 时，如 IndexedDB 成功则允许成功，否则清晰报错并支持直接导出当前内存项目。

### 4.2 功能适配

公共项目管理层只处理项目元数据、隔离和生命周期；业务模块负责默认模型、模型捕获、有效性检查、恢复和重算。新增适配方法职责：

- 创建初始 payload：使用该模块真正的默认模板，不捕获当前已编辑页面冒充默认值。
- 校验 payload：无副作用，不渲染、不写入存储；失败返回原因而不是静默转为空项目。
- 恢复 payload：先完成验证，再替换模型、渲染并重算；不得残留上个项目的行、图片、选择或撤销历史。
- 导出标识：统一项目文件和报告下载文件名中的项目名称；不改变既有报告格式及语言规则。

简单表单可复用通用捕获与恢复；动态行模块保留重建过程。逐一核查 render/reset 是否真正清空模块闭包状态，不能假定重渲染即初始化。

估价和 IEC 启用公共项目管理后，业务编辑不得继续写回单例历史项目；旧键仅作为迁移输入保留。公共材料改动由明确的公共数据适配器导出/恢复，恢复后刷新其内存模型，不能仅改 localStorage 后继续使用旧缓存。

### 4.3 切换与异步隔离

切换顺序为：冻结当前项目标识和版本 → 捕获当前编辑 → 等待持久化 → 验证目标数据 → 解绑旧观察器/清理旧弹窗 → 恢复目标 → 绑定新观察器。

保存失败时保持当前项目和编辑界面，允许重试或导出。恢复目标失败时恢复当前已保存页面，不把默认值写入目标项目。异步附件读取、保存回调和计算结果必须绑定原模块/项目 ID 与会话令牌；切换后不得写入新项目，或用已失效回调覆盖新 UI。

新建项目同样先保存当前项目，再创建默认内容；复制是显式操作，深复制 payload 并创建新项目 ID，不能与原项目共享可变对象。初始化报告状态指沿用现有默认表单/模板和有效默认计算，不显示上一项目的计算结果或“通过”标志。

浏览器刷新恢复各功能最近活动项目；活动项目指针缺失时选择该模块最近可用项目。多标签页同项目发生 revision 冲突时阻止静默覆盖，提示重新加载或另存副本。

## 5. 旧数据保留与迁移

首次升级时，等待旧草稿缓存就绪；每模块把已有有效草稿复制为“原有项目”，无工作内容时创建默认项目。迁移具有幂等标记，只有新容器持久化成功后才写完成标记；失败保留旧数据、可重试，不生成重复项目。

同模块存在统一草稿和历史单例时：以有效统一草稿为主要候选；如历史单例内容不同，保留为独立“历史项目”，不按不可比的时间戳覆盖。与 busbar-temp 兼容相关的旧 rms-current 草稿仍按现有规则读取。

无法读取、损坏或当前不兼容的数据以可导出的隔离条目保留并警告，不伪装成已成功迁移。螺栓旧 K 算法不转成新算法项目，保留其原始数据供备份但明确不可继续校核，不改变既有不迁移规则。

## 6. 本地目录映射和备份格式

目录授权是单向快照导出目标，不是实时镜像。目录句柄仅是本浏览器的便利设置，不写入可搬移备份；权限失效需重新授权。目录名可显示，不承诺获得完整系统路径。

示例结构（功能与项目目录均包含稳定 ID）：

```text
用户选择的备份目录/
  2026-10-21_210000__快照ID/
    manifest.json
    modules/
      螺栓校核__bolt/
        主继电器安装__项目ID/
          project.json
          attachments/
      电池包RLC__conductor/
        800V方案__项目ID/
          project.json
    shared/
      materials.json
      preferences.json
    preserved/
      legacy-data.json
    complete.json
```

manifest 记录格式版本、工具版本、快照 ID、时间、工作区 revision、项目清单、相对路径、文件字节数和 SHA-256。complete 最后写入，包含 manifest 的摘要。恢复只把具有有效完成标记且通过校验的快照认定为完整备份。

项目备份同时包含模型与通用表单。二者出现重复的图片/附件时，以内容摘要去重为快照内部资源引用；恢复时重建原模块所需表示，不能把相对文件路径误交给只接受 Data URL 的旧模型。外部链接不假装成已离线保存的附件；模块实际存储的附件必须可恢复。文件/图片仍遵守模块既有类型与大小限制。

静态代码、官方标准正文、工具内置底库和未导入浏览器的磁盘文件不属于工作内容，不重复备份。用户材料覆盖、新增材料、已存储附件、项目数据、查询草稿、显示设置和隔离的旧数据属于备份范围。原先浏览器下载的 PDF/Excel 不自动回读，也不承诺被备份；需要续做的是项目源数据。

目录和 ZIP 使用相同快照格式。ZIP 复用现有离线 JSZip，不引入在线依赖。文件名经过 Windows 不合法字符、保留名、尾随点/空格处理，并追加 ID；名称不作为恢复路径或模块身份的可信来源。

## 7. 一致性与失败处理

备份先捕获当前编辑并冻结一份全工作区深复制快照；将未持久化但可捕获的内容明确标记为浏览器未保存，允许用户备份保护，不悄悄遗漏。读库失败、模块捕获失败或附件不可读取时不输出“全部备份成功”。

冻结后允许用户继续编辑，备份继续写冻结版本。写完逐文件读回检查，最后写 manifest 与完成标记；目录中已有同名快照则换新 ID，不覆盖历史目录或用户无关文件。失败或取消只留下无完成标记的本次目录，之前完整快照不受影响，不自动递归删除目录。

成功后比较工作区 revision，若已更新则显示“本次备份完成，仍有新修改未备份”。ZIP 生成并发起下载后只能显示“备份包已生成，请确认文件已保存”，不得声称浏览器已确认磁盘写入或读回校验成功。

不做自动备份轮换删除。目录授权拒绝、浏览器不兼容、空间不足、写入/关闭失败、摘要计算失败均显示具体错误，保留浏览器工作内容并提供可用替代导出路径。

## 8. 备份检查、恢复与回退

恢复支持完整快照目录、ZIP 和本功能单项目文件。解析和预检在临时内存区完成，不先修改当前数据。展示版本、时间、功能、项目、公共数据、校验问题；可选择全部、指定功能或指定项目。公共材料和设置是独立选择项，默认不覆盖现有公共数据。

默认以副本恢复，新建项目 ID；要替换时必须明确选择映射目标并二次确认。重名不意味着可自动替换。恢复全部也不删除浏览器中备份里不存在的项目。

替换前将受影响项目、公共数据、活动指针写入可验证的持久恢复点；恢复点保存失败则禁止替换。批量恢复使用暂存批次和提交指针，一批提交对用户要么全部可见，要么失败保留原数据；不能部分写入后显示整体成功。恢复点支持在备份窗口执行回退；回退也先验证，不自动覆盖后来编辑。

损坏的项目或附件不能作为正常项目恢复。允许用户明确选择恢复其余独立有效项目，界面列出跳过项，禁止无提示部分恢复。旧备份格式只允许受支持的显式迁移；未知较新版本拒绝写入，保留当前数据。

恢复后按当前算法重算，保留来源工具/适配版本；版本变化时提示“需要重新校核”，不沿用旧通过状态作为新结论。恢复数据不能修复工具代码或算法缺陷，不擅自更改工程参数。

## 9. 输入边界

所有项目名、备注、备份内容均不可信。遵循现有 `ElectricalSafety` 转义和受限 JSON 解析，拒绝原型污染键、非有限数值、无效 ID/日期/引用。模块导入必须执行本模块结构验证，不能只验证外层 manifest。

拒绝绝对路径、盘符、UNC、反斜杠路径、`.`/`..` 路径段、重复及规范化冲突的 ZIP 路径、外部资源引用；只读清单内允许的相对文件，不执行备份内脚本。初始工作区备份限制为压缩文件 100 MiB、解压总量 200 MiB、最多 10000 文件、单 JSON 10 MiB；附件还受模块现有上限约束。解析前和解压时均检查限额，超限提示拆分备份，不静默截断。

摘要用于检测意外损坏，不证明备份可信；校验通过后仍做安全与业务校验。目录映射不上传用户数据或备份路径到 GitHub/服务端。

## 10. 验证与验收

实现时先建立失败用例，再增加功能，并将新测试加入现有测试调度。

1. 所有计算/校核/文档模块新建、编辑、切换两个项目、刷新、恢复默认值，均不串值；动态行和附件恢复正确。公共资料页状态仍保留。
2. 估价、IEC、原理图、螺栓、DVP、DFMEA、SOR 完整模型专项覆盖；表单模块覆盖动态选择/行重建；报告下载标识当前项目。
3. 旧草稿和历史键迁移幂等，迁移失败不丢原始记录；旧 RMS 和不支持的旧 K 数据按上述规则处理。
4. 模拟存储不可用、配额耗尽、IndexedDB 失败、切换中异步图片完成、多标签页冲突、目标恢复抛错，当前编辑仍可保留/导出。
5. 全量备份含未打开模块、多个项目、公共材料、图片和附件；目录与 ZIP 恢复后的输入、模型、布局及附件内容等价。
6. 目录模拟授权拒绝/撤销、失败/取消、已有目录冲突、写入后读回不一致；失败快照无完成标记，旧快照不变。
7. 备份过程中继续编辑，备份对应冻结 revision，界面明确显示尚未备份的新修改。
8. 恢复默认副本、选择性恢复、确认替换、恢复点回退；损坏摘要/缺失附件/未知版本/不可信路径/原型污染/解压超限均不修改正常数据。
9. 运行完整语法、单元、浏览器、公式与现有报告回归；离线和 file:// 使用路径不依赖网络。真实受支持浏览器人工核验目录授权、分层文件和恢复；自动化目录替身不能替代真实权限验证。
10. 更新 README、全项目 AI 交接和修改日志，说明数据边界、浏览器/本地保存区别与恢复流程；产品版本与发布另行按用户要求执行。

## 11. 实施边界与交付顺序

实施计划应依次覆盖：项目存储与迁移 → 所有模块生命周期和工具栏 → 备份格式与目录/ZIP → 恢复/回退 → 全量回归和文档。每阶段有独立测试，但最终交付应覆盖本设计的两项需求，不以部分模块演示冒充全功能完成。
